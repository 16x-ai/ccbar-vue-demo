# 会话服务后端逻辑（照 `server/` 这一套实现）

本文是**服务端实现说明**：把页面要的那份会话（`WebPhoneSession`）拼出来需要哪些逻辑、每个模块干什么、
有哪些必须守住的不变量。代码级参考实现就是本仓库 `server/` 四个文件；接口字段以
`111.md` 里的平台官方文档为准，两者不一致的地方在第 7 节列出来。

> 姊妹文档：`会话服务实现指南.md` 讲的是**两条平台接口怎么调**（加签、字段、排障）；
> 本文讲的是**后端怎么组织这段逻辑**（模块、流程、决策、移植）。

---

## 1. 职责边界

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| 页面 | 调同源 `POST /get-session`、`POST /set-agent-status`；把结果交给 SDK | 不碰 API KEY/SECRET、不碰 AES 密钥、不拼 SIP 凭据 |
| **会话服务（本文）** | 用服务端凭据换 fs token → 取坐席账号 → 解密 → 拼 WSS → 组装会话；缓存与刷新 | 不存会话、不做业务鉴权（分机/账号应由登录态决定） |
| 平台网关 | 签发 fs token、下发坐席账号与凭据、承担 SIP 注册与呼叫 | — |
| SDK | 拿会话连 WSS、发 REGISTER、通话控制、到点前调 `refreshSession` | 不请求平台接口（4.0.0 起） |

一次会话的寿命 ≈ `expiresIn` 秒，之后 SDK 会再调一次 `refreshSession`，服务端**把整条链路重跑一遍**即可
（等价于换一次 SIP 密码），不需要单独实现刷新逻辑。

## 2. 模块划分（`server/` 四个文件对应的语义）

| 文件 | 语义模块 | 对外契约 |
|---|---|---|
| `get-token.js` | **凭据与签名层**：环境/请求体凭据解析与校验、主机归一化与 SSRF 白名单、签名方式选择、`POST /openapi/v1/token/fs`、fs token 缓存 | `getFsToken({extension, host, appKey, appSecret}) → {code, data:{token, expires}}` |
| `get-session.js` | **会话装配层**：取 fs token → 取坐席账号 → AES 解密 → 拼 WSS → 组装 `WebPhoneSession`；TTL 计算 | `getLegacySession({host, appKey, appSecret, extension, sipWs, registerExpires}) → WebPhoneSession` |
| `set-agent-status.js` | **坐席状态**：`POST /openapi/token/v1/seats/set-status`，body `{extension, status, reason}` | `setSeatStatus({...}) → void` |
| `token-server.js` | **HTTP 外壳（仅本地演示）**：路由 `/get-session`、`/set-agent-status`、`/health`，CORS 与 body 读取 | 生产环境换成你们的框架与登录态 |

移植到其它语言时，就是按这四层各写一个类/模块：**签名层**、**装配层**、**状态层**、**HTTP 层**。

## 3. 主流程（页面调 `/get-session` 之后）

```
① 解析入参（extension / host / KEY / SECRET / sipWs / registerExpires）
   生产环境：extension 与凭据来自服务端登录态，不采信浏览器传的值
② 校验凭据：缺 KEY/SECRET 直接报错，不进网络
③ 主机归一化 + 白名单：补协议、拒绝回环/内网/云元数据地址
④ 取 fs token（带缓存）：见 §4.1
⑤ 取坐席账号：POST {host}/openapi/token/v1/seat/account/get，Authorization 带 fs token，body {}
⑥ 解 SIP 密码：AES-128-CBC/Pkcs7，密文 Base64，key/iv 各 16 字节
⑦ 计算 TTL：min(fs token 剩余, 坐席凭据 expiresIn) − 180，且 ≥ 60
⑧ 拼 WSS 地址：wss://{domain}:{wssPort}…/api/fs/sip-ws?token={fs token}（443 不带端口）
⑨ 组装并返回 WebPhoneSession（字段映射见 §5）
```

失败即中断：**任何一步失败都不要返回一份"半成品会话"**——空密码的会话会让 SDK 在 REGISTER 阶段拿到 401，
比在服务端直接报错难查得多。

---

## 4. 两个关键算法/决策

### 4.1 fs token：签名、缓存

- **签名**（平台文档为准）：`content = MD5(请求体原文)`，
  `canonical = appKey + content + nonce + timestamp`（四个值按 key 升序、仅拼接值），
  `X-Ca-Signature = HMAC-SHA256(canonical, appSecret)` 十六进制小写；
  另需 `X-Ca-Signature-Method: HMAC-SHA256`。
  时间戳与服务器时差 **≤ ±5 分钟**，`nonce` **5 分钟内不得重复**（所以不能复用同一个 nonce 重试）。
- **缓存**：按 `host|extension|appKey` 缓存 token，剩余不足 5 秒重取。每次签入都换票会导致频繁重新注册。
- **两种签名方式**：参考实现对 `x.16x.tech`、`*.yundianlab.com` 用 **md5**（`md5(canonical + secret)`），
  其余主机用 **HMAC-SHA256**，可用环境变量覆盖。移植时建议**默认按平台文档的 HMAC-SHA256**，
  只给老网关留一个开关。

### 4.2 会话 TTL：为什么不是 REGISTER 有效期

`sip.registerTicket`（SIP 密码）本身是一张**有期限的票**，期限由坐席账号接口的 `expiresIn` 给出。
如果会话 TTL 比这张票还长，就会出现「票先过期 → 后续 REGISTER 401」。所以：

```
ttl = max(60, min(fsToken 剩余秒数, 坐席凭据 expiresIn) − 180)
expiresAt = now + ttl
```

- **180 秒**是提前换票缓冲（SDK 自己还会在到点前 60 秒调 `refreshSession`，两层加起来留足余量）。
- `expiresIn` 缺省（平台未启用短时凭据）时用一个保守默认值（参考实现 600）。
- 平台文档里 fs token 的 `expires` 是**到期时间戳（秒）**；参考实现按「大于 86400 就当毫秒」处理，
  结果会被 clamp 到 24 小时——因为外层还有 `min(..., expiresIn)`，实际 TTL 不受影响。
  **移植时建议直接按 `expires − now` 算**，语义更清楚。

## 5. 输出：`WebPhoneSession` 字段映射

| 会话字段 | 取值 | 备注 |
|---|---|---|
| `sessionId` | 服务端生成 | 例如 `legacy-` + 时间戳 base36 |
| `expiresAt` | `now + ttl`（秒） | 见 §4.2 |
| `agent.id` / `externalUserId` / `displayName` / `extension` | 坐席账号的 `username` | 四个字段同值；`status` 固定 `Available` 起步 |
| `sip.uri` | `sip:{username}@{domain}` | |
| `sip.registrar` | `{domain}` | `domain` 是**注册域**，不是 WSS 主机（见 §7 第 3 条） |
| `sip.registerTicket` | 解密后的 SIP 密码明文（或平台的短时注册凭据，见 §7 第 2 条） | 只在服务端与页面之间传递 |
| `sip.registerExpires` | 600（可按入参覆盖） | REGISTER 有效期 |
| `sip.ticketExpiresIn` / `transport.ticketExpiresIn` | 与 `ttl` 同值 | 仅供展示 |
| `transport.wssUrl` | `wss://{domain}:{wssPort}/api/fs/sip-ws?token={fs token}` | 端口 443 不带 `:443`；是否挂 token 可配 |
| `transport.ticket` | `""` | 老平台没有 ticket 子协议，SDK 只声明 `sip` |
| `iceServers` | 优先用坐席账号返回的 `iceServers`；缺省时用 `turnIp:turnPort` 拼 `stun:` | 见 §7 第 1 条 |
| `capabilities` | `outbound/inbound/mute/dtmf/hold/blind_transfer` | 老平台六项都支持 |
| `policy` | 桌面 `maxConcurrentCalls: 2`；**移动 H5 必须打开 `mobileIncomingEnabled`** | 不开 → SDK 删掉 `inbound` → 来电被 480 拒掉 |
| `customerPrefix` / `username` | 坐席账号的对应字段 | SDK 不读；页面显示分机时去前缀用 |

页面侧契约（请求体、成功/失败形态）见 `会话服务实现指南.md` 与 `前端接入文档.md` §7。

## 6. 错误处理、日志与安全

**错误处理**：接口返回非 JSON（常见于把文档站/SPA 域名当 API 主机）、`code != 0`、
网络超时（建议 20 秒）分别给不同的可读信息；平台错误码映射（61 未授权/白名单、65 分机未分配坐席、
55 操作不允许、50 内部错误）要能直接告诉接入方下一步查什么，并把 `traceID` 一并带出。

**日志纪律**（参考实现的做法）：

- 只打印**链路与长度**：`账号=… 前缀=… 密码长度=… 指纹=…`，绝不打印密码、token、`?token=` 的原值；
- 打 WSS 地址时把 `token=` 掩成 `***`；
- 指纹 = `sha256("ccbar-seat-account:" + 密码)` 的前 8 位——便于和页面/别的环境对比是不是同一个密码，且不可逆。

**安全清单**：

- API SECRET、AES key/iv 只存在服务端；页面拿到的只有拼好的会话；
- 主机白名单 + 拒绝回环/内网/云元数据地址（防 SSRF——API 主机是从请求体/配置来的，不能任人填）；
- fs token 与 `registerTicket` 都是凭据：不进日志、不进监控标签、不进工单截图；
- 分机与账号由登录态决定，**不要直接采信浏览器传的 `extension`**（参考实现的入参是为了本地演示方便）。

## 7. 与平台官方文档（`111.md`）的差异与建议

1. **ICE 配置优先用平台返回的 `iceServers`**。平台文档里 `iceServers` 直接是 RTCPeerConnection 可用的列表
   （含 `turn:` 与 TURN 账号密码），还额外给了 `turnUserPassword`。参考实现只用了 `turnIp`/`turnPort` 拼 `stun:`，
   **没有中继**——NAT 复杂的环境会连不上媒体。建议：有 `iceServers` 就原样透传，没有才回退到 `stun:` 拼装。
2. **短时注册凭据 `registerPassword` / `expiresIn`**：平台文档说明 `registerPassword` 是临时注册票、
   `expiresIn` 与它配套（缺省表示未启用）。参考实现用的是长期 `password`、
   但 TTL 已经按 `expiresIn` 算。建议：**有 `registerPassword` 就优先用它**，TTL 严格按 `expiresIn`，
   这样换票节奏和平台一致；没有就继续用 `password` + 保守默认 TTL。
3. **`domain` 是注册域，不一定是 WSS 主机**。参考实现里遇到过「平台给的 domain 是内网名、
   真正要连的是另一个主机名」，所以加了一层兜底：如果 `domain` 明显不可用，就用能连通的主机名（或页面配置的 `sipWs`）。
   移植时保留这个兜底，并允许接入方显式指定 WSS 地址。
4. **`Authorization` 的写法**：平台文档写 `Authorization: Bearer <token>`，而参考实现对老网关发的是
   **不带 `Bearer` 的裸 token**（两者都实测可用）。建议：默认按平台文档带 `Bearer`，
   遇到 61/未授权时把「是否带 Bearer」做成配置项逐个网关试——并优先相信平台文档。
5. **`X-Ca-Signature-Method: HMAC-SHA256`**：平台文档要求带这个头，参考实现的签名层没带。
   建议按文档补上（对老网关无副作用）。
6. **`desktopOnline`**：平台会告诉你这个分机是否被桌面端占用。参考实现忽略了它；
   建议至少在响应里带上标志或写日志，避免和桌面端抢注册时无从排查。
7. **`wsPort` / `wssPort`**：浏览器只能用 `wssPort`（安全上下文要求），不要回退到 `ws:`。

## 8. 移植清单（换语言时逐条对照）

- [ ] 签名：`MD5(请求体原文)` → `canonical = appKey + content + nonce + timestamp` → HMAC-SHA256 → hex；带 `X-Ca-Signature-Method`
- [ ] 时间戳毫秒、`nonce` 不复用（5 分钟内唯一）
- [ ] fs token 缓存键与 5 秒余量
- [ ] `Authorization` 写法按网关可配（先带 `Bearer`）
- [ ] body 必须是 `{}`（空 JSON 对象，不是空字符串）
- [ ] AES-128-CBC / Pkcs7 / 16 字节 key、iv / 密文 Base64 —— key/iv 从配置读，不硬编码进业务代码
- [ ] TTL = `min(fs token 剩余, expiresIn) − 180`，下限 60
- [ ] WSS：`wss://{domain}:{wssPort}{路径}?token={fs token}`，443 不带端口，日志掩码
- [ ] `iceServers` 优先透传，`stun:` 兜底
- [ ] 移动端：`policy.mobileIncomingEnabled = true`
- [ ] 主机白名单 / SSRF 防护
- [ ] 日志不落密码与 token；失败不返回半成品会话
