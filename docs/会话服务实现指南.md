# 自己实现会话服务：两个平台接口怎么调、怎么拼成一份会话

4.0.0 起 SDK 不再请求任何平台接口，它只消费一份**已经拼好的 `WebPhoneSession`**（`sessionProvider.createSession`）。
所以接入方的服务端要做的事就是本文这一条链路：**拿 fs token → 拿坐席账号 → 解出 SIP 密码 → 拼 WSS 地址 → 组装会话**。

参考实现（可与本文逐行对照）：客户 demo 仓库的 `server/get-session.js` 与 `server/get-token.js`，
它们对齐的是老页面 `xcall/ccbar/index.html` 的行为。

```
页面 ──POST /get-session（同源）──▶ 你们的服务端（本文这一条链路）
                                      │ 1) POST {API主机}/openapi/v1/token/fs                ← 加签，拿 fs token
                                      │ 2) POST {API主机}/openapi/token/v1/seat/account/get  ← Authorization: <fs token>
                                      │ 3) AES-128-CBC/Pkcs7 解出 SIP 密码
                                      │ 4) 拼 wss://…/api/fs/sip-ws?token=…
                                      ▼
页面 ◀── 一份完整的 WebPhoneSession ──┘
页面 ──sessionProvider.createSession()──▶ SDK ──▶ 连 WSS、发 REGISTER
```

两条接口都用 `POST` + `application/json`，且都需要服务端持有 **API SECRET**（浏览器拿不到，也不要下发）。

## 1. `POST {API主机}/openapi/v1/token/fs` —— 拿 fs token

### 请求

```http
POST {API主机}/openapi/v1/token/fs HTTP/1.1
Content-Type: application/json
Accept: application/json
X-Ca-Key: <API KEY>
X-Ca-Timestamp: <毫秒时间戳>
X-Ca-Nonce: <随机串，参考实现用 8 字节 hex>
X-Ca-Signature: <见下面的签名算法>

{"extension":"8001"}
```

- **请求体**：`{"extension":"<内部分机号，不含企业前缀>"}`（`extension` 前后空白要去掉）。
- 另有一条**按用户**取票的变体：路径是 `{上面这个路径}/third`，body 为 `{"userId":"…","departmentId":"…"}`。
  按分机取票（上面这条）是最常用的一条。
- **签名算法**（老网关两种都有，按主机选）：

  ```
  content       = 请求体的**原始字符串**（就是 JSON.stringify 之后的那个 bytes 序列）
  contentDigest = md5(content)                      // hex，小写
  canonical     = 按下述顺序直接拼接，无分隔符：
                  appKey + contentDigest + nonce + timestamp
                  （实现上等价于：把 {appKey, content, nonce, timestamp} 四个字段按 key 名排序后取值拼接）
  hmac 方式      signature = HMAC-SHA256(canonical, API SECRET)  // hex
  md5  方式      signature = md5(canonical + API SECRET)         // hex
  ```

  主机的选择规则（参考实现 `pickSignMethod`）：`x.16x.tech` 与 `*.yundianlab.com` 用 **md5**，
  其余主机用 **hmac**；可用环境变量 `CC_API_SIGN=md5|hmac` 覆盖。
  **签错方式的表现是签名校验失败（code != 0）**，不是网络错误，先按主机对一遍。

  ```js
  // Node，等价于参考实现里的 createAuthentication（apiSecret 从环境变量读，不下发浏览器）
  const md5 = (v) => crypto.createHash('md5').update(v, 'utf8').digest('hex');
  const canonical = [appKey, md5(body), nonce, String(Date.now())].join('');
  const signature = method === 'md5'
    ? md5(canonical + apiSecret)
    : crypto.createHmac('sha256', apiSecret).update(canonical, 'utf8').digest('hex');
  ```

  注意：只有这四个 `X-Ca-*` 头，**没有** `X-Ca-Signature-Method`（那是另一条 WebPhone Token 接口的写法，与本链路无关）。

### 响应

```json
{ "code": 0, "data": { "token": "<fs token>", "expires": 3600 } }
```

- `code !== 0` 即失败，错误原因通常在 `message` 里。
- `expires` 有的环境回**秒**、有的回**毫秒**：参考实现的判定是「大于 86400 就当毫秒」，再做秒数换算。
- **建议缓存**：按 `host|extension|appKey` 缓存，剩余有效期不足 5 秒就重取（参考实现 `getFsToken`）。
  每次都取会导致注册频繁换票。

## 2. `POST {API主机}/openapi/token/v1/seat/account/get` —— 拿坐席账号

### 请求

```http
POST {API主机}/openapi/token/v1/seat/account/get HTTP/1.1
Content-Type: application/json
Accept: application/json
Authorization: <上一步拿到的 fs token>

{}
```

**两个最容易踩的点**：
1. `Authorization` 是 **fs token 原样**，**没有 `Bearer` 前缀**；
2. body 是 **`{}`**（空 JSON 对象），不能省略、也不能传别的字段。

### 响应

```json
{
  "code": 0,
  "data": {
    "username": "p8001",
    "customerPrefix": "p",
    "password": "<Base64 的 AES 密文>",
    "expiresIn": 600,
    "domain": "sip.example.com",
    "wssPort": 7443,
    "turnIp": "1.2.3.4",
    "turnPort": 3478
  }
}
```

服务端会用到的字段：

| 字段 | 用途 |
|---|---|
| `username`（有的环境叫 `account`） | **坐席账号**：SIP 注册用户名，也是设置坐席状态时要传的 `extension`（可能带企业前缀，例如账号 `p8001` 对应用户填的 `8001`） |
| `customerPrefix` | 企业前缀，页面显示分机时要去掉；内呼时又要把前缀拼回号码前 |
| `password` | SIP 密码的 **AES 密文**（Base64），下一步解密 |
| `expiresIn`（或 `expires_in`） | **SIP 密码这张票的有效期（秒）**，决定会话 TTL，见第 4 步 |
| `domain` | SIP 域名：拼 `sip.uri` / `registrar`，也是 WSS 地址的兜底主机 |
| `wssPort` | 软电话端口，缺省 7443（443 时地址里不带端口） |
| `turnIp` / `turnPort` | ICE 的 STUN 地址，端口缺省 3478 |

## 3. 解出 SIP 密码（AES）与拼 WSS 地址

这两步不在平台接口里，但不做会话就是残缺的。

**AES 解密**：AES-128-CBC / Pkcs7，key 与 iv 各 **16 字节**（老网关是固定值），密文按 **Base64** 处理；
等价于 `CryptoJS.AES.decrypt(cipher, key, { iv, mode: CBC, padding: Pkcs7 })`。

```js
const decipher = crypto.createDecipheriv('aes-128-cbc', Buffer.from(AES_KEY, 'utf8'), Buffer.from(AES_IV, 'utf8'));
const password = Buffer.concat([
  decipher.update(Buffer.from(encrypted, 'base64')),
  decipher.final(),
]).toString('utf8');
```

- **key/iv 只放服务端**，不要写进页面。
- 解密失败或结果为空要**在服务端直接报错**，不要下发一份空密码的会话（SDK 会在 REGISTER 阶段拿到 401，更难查）。
- 排障小技巧（参考实现）：只打印密码的**长度 + 加盐哈希前 8 位**，不打印密码本身，就能和页面控制台里的值对比确认两边拿到的是同一个密码。

**WSS 地址**：

```
wss://{domain}:{wssPort || 7443}/api/fs/sip-ws?token={fsToken}     // 端口 443 时地址里不带 :443
```

- `domain` 缺失或指向内网名时，用实际能连通的软电话主机名兜底（参考实现 `sipDomainOf`）。
- 是否把 fs token 挂到 `?token=` 上：老页面（能打通外呼的那套）**不挂**，token 只用在 HTTP 接口的 `Authorization`；参考实现做成可配（`CC_SIP_WS_TOKEN=0` 不挂），默认沿用历史行为（挂）。
- 这个地址最终写进会话的 `transport.wssUrl`；页面上若是相对路径，SDK 会用构造参数 `baseUrl` 解析它。

## 4. 组装成 `WebPhoneSession`

把上面拿到的东西映射成 SDK 会读的字段（完整字段表见 [api/client.md](../api/client.md)）：

| 会话字段 | 取值 |
|---|---|
| `sip.uri` | `sip:{username}@{sipDomain}` |
| `sip.registrar` | `{sipDomain}` |
| `sip.registerTicket` | 第 3 步解出来的 **SIP 密码明文** |
| `sip.registerExpires` | REGISTER 有效期（秒），没特殊要求就用 600 |
| `transport.wssUrl` | 第 3 步拼出的 WSS 地址 |
| `transport.ticket` | 旧平台没有 ticket 子协议 → **空串**（SDK 只声明 `sip`） |
| `iceServers` | `turnIp` 有值则 `[{ urls: ['stun:{turnIp}:{turnPort||3478}'] }]`，否则 `[]` |
| `capabilities` | 老平台六项都支持：`outbound / inbound / mute / dtmf / hold / blind_transfer` |
| `policy` | 桌面 `maxConcurrentCalls: 2`、`incomingEnabled: true`；移动 H5 还要 `mobileIncomingEnabled: true`（否则 SDK 会删掉 `inbound`，来电被 480 拒掉） |
| `expiresAt` | **`now + min(tokenTtl, seatTtl) - 180`**，且不小于 60（见下） |
| `sessionId` | 服务端自己生成的标识即可 |

**TTL 为什么要取两者较小值再减 180 秒**：`sip.registerTicket` 是「票」，有效期由坐席账号接口的 `expiresIn` 决定；
fs token 也有自己的 `expires`。SDK 会在会话到期前 60 秒调 `refreshSession`，如果会话 TTL 比票还长，
就会出现「票先过期 → 后续 REGISTER 401」。参考实现额外留 180 秒缓冲（`PASSWORD_REFRESH_BUFFER`）。

最小可用的返回示例：

```json
{
  "sessionId": "legacy-abc123",
  "expiresAt": 1789000000,
  "agent": { "id": "p8001", "externalUserId": "p8001", "displayName": "p8001", "extension": "p8001", "status": "Available" },
  "sip": { "uri": "sip:p8001@sip.example.com", "registrar": "sip.example.com", "registerTicket": "<明文密码>", "registerExpires": 600, "ticketExpiresIn": 420 },
  "transport": { "wssUrl": "wss://sip.example.com:7443/api/fs/sip-ws?token=<fs token>", "ticket": "", "ticketExpiresIn": 420 },
  "iceServers": [{ "urls": ["stun:1.2.3.4:3478"] }],
  "policy": { "maxConcurrentCalls": 2, "incomingEnabled": true, "mobileIncomingEnabled": false, "backgroundCallingSupported": false },
  "capabilities": ["outbound", "inbound", "mute", "dtmf", "hold", "blind_transfer"]
}
```

`refreshSession` 直接把这一整条链路再跑一遍即可（等价于换一次 SIP 密码），不必单独实现。

## 页面对服务端的契约

| 项 | 值 |
|---|---|
| 方法/路径 | `POST /get-session`（同源；地址可用 `VITE_SESSION_API` 改） |
| 请求体 | **演示用的本地代理模式**会带分机与凭据（`host` / KEY / SECRET / `sipWs` / `registerExpires`）；换成你们自己的后端后，这些都应由服务端登录态决定，请求体可以只有 `{}` |
| 成功响应 | 一份完整的 `WebPhoneSession`（见上），HTTP 200 |
| 失败 | 非 200，或 body 里带 `message` —— 页面会显示在红字行 |

坐席状态另走一个同源接口（空闲 / 置忙 / 休息 / 退签），服务端再带 fs token 请求
`POST {API主机}/openapi/token/v1/seats/set-status`，body `{ extension, status, reason }`，
其中 **`extension` 传坐席账号**（不是用户填的分机号），`status` 只有 `Available` / `On Break` / `Logged Out`。

## 环境变量（参考实现里可配的项）

| 变量 | 作用 | 默认 |
|---|---|---|
| `CC_API_HOST` / `CC_API_APP_KEY` / `CC_API_APP_SECRET` | API 主机与凭据（本地代理模式下也可由请求体带） | 无 |
| `CC_FS_TOKEN_PATH` | fs token 路径 | `/openapi/v1/token/fs` |
| `CC_SEAT_ACCOUNT_PATH` | 坐席账号路径 | `/openapi/token/v1/seat/account/get` |
| `CC_SEAT_STATUS_PATH` | 坐席状态路径 | `/openapi/token/v1/seats/set-status` |
| `CC_SIP_WS_PATH` | 软电话路径 | `/api/fs/sip-ws` |
| `CC_API_SIGN` | 强制签名方式 | 按主机自动判（见第 1 步） |
| `CC_SIP_WS_TOKEN` | 是否把 fs token 挂到 WSS 的 `?token=` | `1`（挂） |

## 排障对照

| 现象 | 先查什么 |
|---|---|
| 「接口返回了非 JSON 响应」 | API 主机填成了文档站 / SPA 域名；或路径被前端路由吞了 |
| `code != 0` + 签名相关报错 | 签名方式选错（md5 vs hmac）、`content` 不是**原始请求体字符串**、时间戳不是毫秒 |
| `code != 0` + 账号相关报错 | 分机号带没带企业前缀；账号在该网关下是否存在 |
| 解密后密码为空 | 密文被截断、base64 没解、key/iv 用了别的环境的 |
| 注册成功后一段时间开始 401 | 会话 TTL 比 SIP 密码票长（见第 4 步的 180 秒缓冲） |
| 一切正常但连不上软电话 | `domain` 是内网名；`wssPort`/路径不对；自签名证书先在浏览器里信任一次 |
| 服务端要防 SSRF | 参考实现会拦回环、内网与云元数据地址（`169.254.169.254`、`metadata.google.internal` 等），并只允许 http(s) 主机 |
