# CCBar WebPhone 前端接入文档（Vue 3 示例）

## 首通结论

- 页面上只有**一个**接口：`POST /get-token`（同源；用来加签的 API SECRET 只留在服务端）。
- SDK 拿到票之后自动完成：取坐席账号 → 解出 SIP 密码 → 组装会话（软电话地址用你传进来的）→ 发 REGISTER。
- 换票之后的所有请求都是 SDK 从**浏览器直接**打平台的，页面不碰 AES 密钥，也不依赖网关的跨域配置。
- 收到 `connection.registered`（页面标签变「已注册」）之后才能外呼。

## 前置条件

- Node.js **22.18 或更高版本**，以及能跑 Vite 的 npm。
- 页面运行在 HTTPS 或 localhost 安全上下文，浏览器允许麦克风访问。
- 软电话服务若是自签名证书，先在浏览器里直接访问一次该域名并信任证书，否则 SIP 的 WebSocket 建不起来。
- 需要向服务商取得这几项，并在页面「设置」里填写（前四项必填，最后一项可留空）：

| 信息 | 用途 | 示例 |
|---|---|---|
| API 主机（接口网关地址） | 取票口打平台接口的地址前缀，也是 SDK 取坐席账号的地址前缀 | `https://vxapi.yundianlab.com` |
| API KEY / API SECRET | 换票加签用；生产环境**只放在服务端** | — |
| 内部分机号 | 分机号，不含企业前缀 | `8001` |
| 软电话 WSS 地址 | 必填：会话里的 `transport.wssUrl` 直接用它（完整地址，SDK 不拼） | `wss://你们的域名/api/fs/sip-ws` |
| SIP 注册有效期 | 可留空，默认 600 秒（10–3600），由 SDK 写进会话的 `sip.registerExpires` | `600` |

## 安装 SDK

```bash
npm install @16x/webphone-sdk
```

本链路用到两个入口：根入口的 `CCBarClient`，以及子入口 `@16x/webphone-sdk/legacy` 的 `createLegacySessionProvider`（换票 → 组装会话的实现）。


## 五分钟跑起来（本示例）

```bash
cd ccbar-vue-demo
cp .env.example .env      # Windows: copy .env.example .env
npm install
npm run dev               # 页面 http://127.0.0.1:5173 ；取票服务 http://127.0.0.1:3100
```

打开页面 →「设置」填 **API 主机 / API KEY / API SECRET / 内部分机 / 软电话 WSS**（这五项都必填）→「保存」→「签入」。
（设置改完不必刷新页面：点「签入」时会按当前设置重建客户端。）

预期现象：

| 步骤 | 看到什么 |
|---|---|
| 签入 | 全屏「正在签入…」，日志出现 `请求取票口 …` → `取票成功` → `坐席账号就绪` → `connection=connecting` → `connection=connected` → `connection.registered`（最后一行记在 `SIP` 页签）；SIP 标签变「已注册」 |
| 外呼 | 服务标签「呼出中 → 振铃中 → 通话中」；`SIP` 页能看到 `INVITE` 原文与响应 |
| 来电 | 页面弹出来电浮层，可「接听 / 拒接」 |
| 保持 / 恢复 / 转接 / 挂断 | 作用于当前这一路通话；转接读「号码」框里的号码 |
| 空闲 / 置忙 / 休息 | 全屏「正在设置坐席状态…」，成功后坐席标签相应变化 |
| 退签 | `connection=offline`，分机号消失 |

## 浏览器端初始化

```ts
import { CCBarClient } from "@16x/webphone-sdk";
import { createLegacySessionProvider } from "@16x/webphone-sdk/legacy";

const sessionProvider = createLegacySessionProvider({
  host: "https://你们的接口网关",
  // 必填：软电话 WSS 地址（wss:// 或 ws:// 的完整地址）。SDK 只在它上面挂 ?token=，不按账号域名拼
  sipWsUrl: "wss://你们的域名/api/fs/sip-ws",
  // 页面只提供换票口；加签与 SECRET 都在服务端
  getToken: async () => {
    const response = await fetch("/get-token", {
      method: "POST",
      credentials: "omit",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ extension: "8001" }),
    });
    return response.json(); // { code: 0, data: { token, expires } }
  },
});

const client = new CCBarClient({
  platform: "web",
  sessionProvider,
});

await client.initialize();
await client.connect();                                  // 换票 → 取账号 / 解密 / 拼会话 → REGISTER

const call = await client.dial({ destination: "9196" });
await call.hangup();

await client.disconnect();                               // 退签：挂断通话、停 SIP
await client.dispose();                                  // 释放 WebSocket / PeerConnection / 定时器 / 订阅
```

要点：

- 一个页面只留**一个** `CCBarClient` 实例，重复创建会出现两个 REGISTER 抢同一个坐席。
- 页面卸载或组件销毁时必须 `dispose()`；Vue 里放在 `onBeforeUnmount`。
- `dial` / `answer` 这类方法在未签入时是**同步抛错**，调用点要 `try/catch`。
- 会话策略：`registerExpires` 默认 600 秒，本示例用设置里的「SIP 注册有效期」；来电由会话策略 `incomingEnabled`（默认 `true`）与能力白名单里的 `inbound` 决定。
- **移动端形态**：本示例写死 `platform: "web"`（桌面形态），所以手机浏览器也按桌面策略接来电（并发 2 路、有保持/转接）。要用移动端形态就传 `platform: "mobile-web"`：SDK 会砍掉保持/转接，并且**只有会话策略里 `mobileIncomingEnabled: true` 才接来电**（缺省当不能接，来电会被 480 拒掉）。
- 用不到就不必传的选项：`locale`（只是把语言偏好随会话请求传给你们的取票口，SDK 不据此改行为）、`requestedCapabilities`（能力白名单，默认全开）。

## 坐席状态（空闲 / 置忙 / 休息 / 退签）

空闲 / 休息由 `client.setAgentStatus('available' | 'break')` 触发；「置忙」走同一个平台接口，只是 `reason` 不同。平台只有三个状态值：

| 页面上 | 平台 status | reason |
|---|---|---|
| 空闲 | `Available` | `空闲` |
| 置忙 | `On Break` | `忙碌` |
| 休息 | `On Break` | `休息` |
| 退签 | `Logged Out` | 空 |

```http
POST {API主机}/openapi/token/v1/seats/set-status
Authorization: <fs token>
Content-Type: application/json

{ "extension": "p8001", "status": "On Break", "reason": "忙碌" }
```

- `extension` 传的是**坐席账号**（`seat/account/get` 返回的 `username`，可能带企业前缀）：平台按账号查坐席，传用户填的分机号会回 `{"code":-1,"message":"Data not found"}`。
- 这一步用的是会话里那张票，**不会再换一次票**；退签时会顺带置一次 `Logged Out`（失败只写日志，不阻塞退签）。

## 业务 API 与事件

| 页面操作 | SDK 调用 |
|---|---|
| 签入 | `client.connect()`（内部先 `initialize()`，再换票 → 拼会话 → REGISTER） |
| 退签 | `client.disconnect()` |
| 外呼 | `client.dial({ destination })` |
| 外呼 / 内呼带自定义参数 | `client.dial({ destination, userdata })`：写进 INVITE 的 `X-User-Data` 头，由平台/服务端读。只放行**可见 ASCII**（换行会构成 SIP 头注入，中文/JSON 请先编码），留空即不带这个头。本示例页面上没有输入框，代码里的 `USERDATA` 常量恒为空 |
| 内呼 | `client.dial({ destination: 企业前缀 + 分机号 })`：平台靠「前缀 + 分机号」认内线 |
| 挂断 / 保持 / 恢复 / 转接 | 当前通话上的 `hangup()` / `hold()` / `resume()` / `transfer({ type: 'blind', target })` |
| 接听 / 拒接 | `client.answer(callId)` / `call.reject({ reason })`（`callId` 来自 `call.incoming`） |
| 空闲 / 休息 | `client.setAgentStatus('available' \| 'break')` |
| 置忙 | 直接调会话来源的 `setAgentStatus({ status: 'break', reason: '忙碌' })`（SDK 的 `client.setAgentStatus` 没有 busy 取值），落到同一个平台接口 |
| 取当前通话 | `client.getActiveCall()`（未接通时用 `getCalls()` 找第一路未结束的通话） |
| 放远端声音 | `client.media.playRemoteAudio(callId)` —— 浏览器拦掉自动播放时，在点击手势里补放 |
| 清空日志 | 页面自己处理（`clearLog(panel)`），不经过 SDK |

`client.on(事件名, 处理函数)` 返回取消订阅的函数，页面卸载时要调用：

| 事件 | 何时触发 |
|---|---|
| `connection.stateChanged` / `connection.registered` / `connection.reconnecting` / `connection.failed` | 连接与注册状态变化 |
| `token.expiring` / `token.refreshed` | 会话将过期 / 已刷新 |
| `agent.statusChanged` | 坐席状态变化 |
| `call.created` / `call.incoming` / `call.stateChanged` / `call.activeChanged` / `call.ended` / `call.failed` | 通话生命周期 |
| `error` | 其他 SDK 错误 |

## 配置项（环境变量）

除了页面设置，取票口与本地取票服务还有这些可配项（`.env` 或构建时注入）：

| 变量 | 作用 |
|---|---|
| `VITE_REF_TOKEN_API` | 取票口地址，默认同源 `/get-token` |
| `REF_TOKEN_PORT` | 本地示例取票服务的端口，默认 3100（占用时自动往后找） |
| `CC_API_HOST` / `CC_API_APP_KEY` / `CC_API_APP_SECRET` | 示例取票服务打平台接口的兜底配置（页面设置里的值优先） |
| `VITE_API_HOST` | 构建时注入默认「API 主机」（不注入就留空，用户在设置里填） |
| `VITE_SIP_KEEPALIVE` | SIP 保活间隔（秒），本示例默认 600＝不额外发心跳，只由 JsSIP 每 10 分钟续一次注册（**SDK 自身默认是 25 秒**，本示例显式设成 600） |

另有几个只与本地示例有关的变量（`CCBAR_DEMO` / `CCBAR_BIND` / `PORT` / `CC_EXTENSION` / `CCBAR_LOCAL_SDK`）；换成你们自己的后端后都不需要。

线上部署：`npm run build` 出的是纯静态 `dist/`，同源请求要把 `/get-token` 反代到你们的取票服务，或者构建时把 `VITE_REF_TOKEN_API` 指到它的地址（细节见仓库 README「部署注意」）。

## 日志与排障

面板分两个页签：**日志**（流程：签入、取票、坐席账号、连接与通话状态）与 **SIP**（REGISTER / INVITE 原文与 SDK 的 `call.*` 事件明细）。每行格式 `HH:MM:SS.mmm [来源] 内容`，绿=成功、黄=提醒、红=错误；`token=` 与 `"password"` 会自动打码。

| 现象 | 优先检查 |
|---|---|
| 点签入报「取票」失败 | 取票口不通：`/get-token` 没反代到、或取票服务没在跑（`npm run dev` 会一起起） |
| 点签入报「取坐席账号失败（HTTP 4xx/5xx）」 | 网关没有 `seat/account/get`，或那张票没权限、调用方出口 IP 不在白名单 —— 换票与取账号是两条不同的平台接口 |
| 点「置忙 / 休息 / 空闲」报 `Data not found` | 平台按**坐席账号**查坐席：账号没绑好就会这样 |
| 点「置忙 / 休息」报「返回了非 JSON 响应」 | 网关没有 `seats/set-status`（或路径被前端路由吞了）：这一步由 SDK 从浏览器直接打平台，不经过页面自己的后端 |
| 报 `CONFIG_INVALID` | 软电话 WSS 没传、传了相对路径或 `http(s)://` —— 这一项由接入方提供，SDK 不拼。（本示例里它是必填项，空值会被页面自己的校验先拦下并给中文提示） |
| 一直是「连接中」 | 软电话 WSS 地址、证书、端口、路径；自签名证书先信任一次 |
| 打不通 / 提示「话机未连接，请先签入」 | 等 SIP 标签变「已注册」再呼叫 |
| 分机显示带前缀 | 坐席账号形如 `p8001`，页面会去掉前缀后显示 |
| 挂断后页面还有声音 | 组件销毁要 `dispose()`；本示例在 `onBeforeUnmount` 里做 |
| 刚签入第一通必失败、第二通正常 | 平台行为：每次注册后的首个外呼会回 `480`（`Q.850;cause=16`），几秒内自愈。页面**不自动重拨**，再拨一次即可；要根治需平台侧查同一次签入里两条 INVITE 的 Call-ID |
| 聊到一半突然断、SIP 面板里搜不到 `ACK` | 平台/SBC 没回 ACK：JsSIP 会重发 200 OK 等它，**32 秒还没等到就以 `NO_ACK` 结束通话**。需平台侧补齐 ACK |

SIP 原文是示例页的排障能力：SDK 没有公开读 SIP 报文的接口，页面通过打开 JsSIP 的 debug 命名空间（`localStorage.debug = 'JsSIP:*'`）拿到原文，再拦截 console 写进面板。这属于未公开的调试能力，升级 SDK 时要复查。

## 安全与上线清单

**API KEY、API SECRET、token、SIP 密码不得出现在前端源码、日志、URL 或代码仓库里。**

- [ ] 前端构建产物不包含 API SECRET、固定 token 或 SIP 密码（本示例里 KEY / SECRET 只在设置弹窗与取票请求体里；换成你们自己的后端后，这两个字段可以留空）。
- [ ] 取票口只向已登录用户发分机对应的票，分机取自登录态，不采信浏览器提交的值。
- [ ] 平台返回的 SIP 密码密文经过页面是设计内的事（SDK 在会话入口解）；**明文**只应存在内存里，不要打进日志、不要落盘、不要拼进 URL。
- [ ] 页面与取票口保持同源（或取票口回正确的 CORS 头），生产建议统一用 API 域名。
- [ ] 浏览器有麦克风权限和可用输入设备；页面在用户可理解的时机申请权限。
- [ ] 页面卸载、登出和异常路径都能释放通话与媒体资源（`disconnect()` + `dispose()`）。
- [ ] 逐项验收：签入 → 注册 → 来电弹屏 → 接听 → 外呼 → 保持/恢复 → 转接 → 挂断 → 退签 → 刷新页面重签。
