# CCBar 前端接入文档（Vue 3 示例）

本文对应本仓库里的可运行示例：一个 Vue 3 页面 + 一个本地 Node 代理，软电话能力来自 npm 包
`@16x/webphone-sdk`。接口、字段和行为以本文与仓库源码为准；换 SDK 版本时请对照它的 `CHANGELOG.md`。

> 旧版脚本式 SDK（`window.CCBarSDK` + `<script>` 引入）的对接文档是另一份。两者的 API 对照见
> 本文第 11 节，便于按老文档接入过的同学快速迁移。

## 1. 接入前准备

### 1.1 环境要求

- 页面必须运行在 **HTTPS 或 localhost**：浏览器只在安全上下文里给麦克风权限。本地开发用
  `http://127.0.0.1:5173` 即可。
- 浏览器需支持 WebRTC、WebSocket 与麦克风；首次使用要允许本站点访问麦克风。
- 若软电话服务用的是自签名证书，先直接用浏览器访问一次那个域名并信任证书，否则 SIP 的
  WebSocket 建不起来。

### 1.2 需要向服务商确认的信息

| 信息 | 用途 |
|---|---|
| API 主机（接口网关地址） | 取 Token / 取会话的地址前缀，例如 `https://call-ng.innopaas.com` |
| API KEY / API SECRET | 服务端签名用；**只放在服务端**，不下发到浏览器 |
| 内部分机号 | 坐席账号，例如 `8001`（不含企业前缀） |
| 平台形态 | 默认走旧平台（`token/fs` + `seat/account/get`）；网关若部署了 `/webphone/v1/*`，构建时用 `VITE_LEGACY_PLATFORM=0` 切，见第 7 节 |
| 软电话 WSS 地址 | 页面上是**必填**项，例如 `wss://你们的域名/api/fs/sip-ws`；由服务端拼进会话的 `transport.wssUrl` |

## 2. 五分钟跑起来

```bash
cd ccbar-vue-demo
cp .env.example .env      # Windows: copy .env.example .env
npm install
npm run dev               # 页面 http://127.0.0.1:5173 ；本地代理 http://127.0.0.1:3000
```

打开页面 →「设置」填 **API 主机 / API KEY / API SECRET / 内部分机** →「保存」→「签入」。

预期现象：

| 步骤 | 看到什么 |
|---|---|
| 签入 | 全屏「正在签入…」，随后 `日志` 页出现 `开始签入 …` → `connection=connecting` → `connection.registered`；SIP 标签变「已注册」、坐席标签变「在线」，标题栏出现 `前缀 200002 · 分机 10006` |
| 外呼 | 服务标签「呼出中 → 振铃中 → 通话中」；`SIP` 页能看到 `INVITE` 原文与响应 |
| 来电 | 页面弹出来电浮层，可「接听 / 拒接」 |
| 保持 / 恢复 / 转接 / 挂断 | 作用于当前这一路通话；转接读「号码」框里的号码 |
| 空闲 / 置忙 / 休息 | 全屏「正在设置坐席状态…」，成功后坐席标签相应变「在线 / 忙碌 / 休息」 |
| 退签 | `connection=disconnected`，分机号消失 |

## 3. 代码结构与数据流

```
浏览器
├── src/App.vue                        页面骨架：状态标签 + 号码框 + 三行按钮 + 日志卡片
├── src/components/
│   ├── SettingsDialog.vue             设置弹窗
│   ├── LogPanel.vue                   日志卡片（日志 / SIP 两个页签）
│   └── IncomingCallModal.vue          来电浮层
├── src/lib/
│   ├── usePhone.ts                    页面逻辑：状态、动作、SDK 事件 → 页面状态与日志
│   ├── session.ts                     会话来源（默认 sessionProvider；可选 tokenProvider）
│   ├── settings.ts                    设置读 / 校验 / 写 localStorage
│   ├── sipDebug.ts                    SIP 原文（打开 JsSIP debug + 接 console）
│   ├── logs.ts                        日志格式化与状态文案（纯函数，可单测）
│   └── helpers.ts                     地址校验、分机前缀处理
└── server/                            只在本地演示用的代理（生产换成你们自己的后端）
    ├── token-server.js                HTTP 服务：/get-session、/set-agent-status、/get-token、/health
    ├── get-token.js                   fs token（X-Ca 签名）；新平台形态还用它请求 /webphone/tokens
    ├── get-session.js                 默认形态：token/fs → seat/account/get → 解出 SIP 密码
    ├── set-agent-status.js            坐席状态：seats/set-status（空闲 / 置忙 / 休息 / 退签）
    └── dev.mjs                        一条命令同时起 Vite 和上面的代理
```

数据流一句话：**按钮 → `usePhone` 的动作 → SDK → 事件回到 `usePhone` → 页面状态与日志。**

页面本身很薄：`App.vue` 只负责把状态绑到标签上、把点击交给动作。要复用的话，把 `src/lib` 四个文件
（`usePhone.ts`、`session.ts`、`settings.ts`、`sipDebug.ts`，以及它们依赖的 `logs.ts`、`helpers.ts`）
拷进你们的 Vue 项目即可，不依赖本仓库的样式与组件。

## 4. 签入、退签与生命周期

页面在 `onMounted` 时建一个客户端（`usePhone.ts` 的 `mount()`），整个页面共用一个实例：

```ts
import { CCBarClient } from "@16x/webphone-sdk";

const client = new CCBarClient({
  locale: "zh-CN",
  platform: "web",
  // 会话来源二选一，见第 7 节：
  sessionProvider, // 默认：由我们自己的服务端把会话拼好（旧平台网关）
  // tokenProvider, // 可选：SDK 拿 token 自己去换会话（网关有 /webphone/v1/*）
  sharedWorker: { enabled: false, fallback: "single-tab" }, // 演示页单标签页
});

// 签入：内部会取会话 → 连 WSS → 发 REGISTER
await client.connect({ extension: "8001" });

// 退签：挂断通话、停 SIP、删会话；可重复调用
await client.disconnect();

// 页面卸载：释放 WebSocket / PeerConnection / 定时器 / 事件订阅
await client.dispose();
```

注意两点：

- **签入之前必须先填设置**：页面点「签入」时会先校验设置（`settings.ts` 的 `normalizeConfig`），
  不合格就只在红字行报错，不会去连网关。
- **`disconnect()` 与 `dispose()` 不一样**：前者只是退签，之后还能再签入；后者把实例销毁，
  页面卸载或组件销毁时调用（Vue 里放在 `onBeforeUnmount`）。

## 5. 业务 API

页面按钮和 SDK 调用的对应关系（全部在 `src/lib/usePhone.ts`）：

| 页面操作 | SDK 调用 | 说明 |
|---|---|---|
| 签入 | `client.connect({ extension })` | 取会话并 REGISTER |
| 退签 | `client.disconnect()` | 挂断通话、停 SIP |
| 外呼 | `client.dial({ destination })` | `destination` 是「号码」框里的号码 |
| 内呼 | `client.dial({ destination: 前缀 + 分机号 })` | 旧平台靠「企业前缀 + 分机号」认内线（`prefixExtension()`）；`type: 'extension'` 只是加个 `X-XCall-Destination-Type` 头，平台不认 |
| 挂断 | `call.hangup()` | 作用在「当前通话」上 |
| 保持 | `call.hold()` | 未接通时不可用 |
| 恢复 | `call.resume()` | |
| 转接 | `call.transfer({ type: 'blind', target })` | 盲转；号码取自「号码」框 |
| 接听 | `client.answer(callId)` | `callId` 来自 `call.incoming` 事件 |
| 拒接 | `call.reject({ reason: '已拒接' })` | |
| 空闲 / 休息 | `client.setAgentStatus('available' \| 'break')` | 落到平台的坐席状态接口（Available / On Break+休息） |
| 置忙 | 页面直接调 `setSeatStatus(config, 'On Break', '忙碌')` | SDK 没有 busy 取值，走同一个平台接口，用 reason 区分忙碌与休息 |
| 取当前通话 | `client.getActiveCall()` | 没接通时用 `getCalls()` 找第一路未结束的 |
| 放远端声音 | `client.media.playRemoteAudio(callId)` | 浏览器拦截自动播放时，在点击手势里补放 |

用法示例：

```ts
// 外呼：号码原样拨
await client.dial({ destination: "10086" });

// 内呼：拼上企业前缀再拨（账号是 p8001 时，前缀就是 p）
await client.dial({ destination: prefixExtension("1002", "p") }); // → p1002

// 操作「当前这一路」通话
const call = client.getActiveCall() ?? client.getCalls()[0];
await call?.hold();
await call?.resume();
await call?.transfer({ type: "blind", target: "1003" });
await call?.hangup();
```

页面用 `run(动作名, 动作)` 统一包了一层：执行期间禁用按钮防重复点击、结束时清掉上一次的错误、
失败时把错误的 `message` 写到红字行。`dial` / `answer` 这类方法在未签入时是**同步抛错**，
所以调用点必须 `try/catch`（`run` 已经做了）。

### 5.1 坐席状态（空闲 / 置忙 / 休息 / 退签）

平台的坐席状态只有三个值，「忙碌」和「休息」都是 `On Break`，靠 `reason` 区分（对齐 xcall fork
的 `ccbar.js`），所以页面对服务端的契约是：

| 页面上 | 平台 status | reason |
|---|---|---|
| 空闲 | `Available` | `空闲` |
| 置忙 | `On Break` | `忙碌` |
| 休息 | `On Break` | `休息` |
| 退签 | `Logged Out` | 空 |

```ts
// 服务端：POST {API主机}/openapi/token/v1/seats/set-status
// 请求头 Authorization: <fs token>，body：
{ extension: "p8001", status: "On Break", reason: "忙碌" }
```

注意 `extension` 传的是**坐席账号**（`seat/account/get` 返回的 `username`，可能带企业前缀，例如用户填 `8001`、账号是 `p8001`）：
平台按账号查坐席，传用户填的分机号会回 `{"code":-1,"message":"Data not found"}`。页面上的「号码/分机」输入框只用于外呼，不用于这里。

页面上：`空闲` / `休息` 走 `client.setAgentStatus(...)`（SDK → 会话来源 → 上面的接口），
`置忙` 因为 SDK 没有 busy 取值，由页面直接调 `setSeatStatus()`；`退签` 时会顺带置一次
`Logged Out`（失败只写日志，不阻塞退签）。

## 6. 事件与状态

用 `client.on(事件名, 处理函数)`订阅，返回一个取消订阅的函数（页面卸载时要调用）。
`usePhone.ts` 的 `subscribe()` 里就是完整的订阅清单：

| 事件 | 何时触发 | 页面用它做什么 |
|---|---|---|
| `connection.stateChanged` | 连接状态变化 | 更新 SIP 标签、写日志 |
| `connection.registered` | REGISTER 成功 | SIP 标签变「已注册」，显示分机号 |
| `connection.reconnecting` | 断线重连中 | 提示重连次数 |
| `connection.failed` | 连接/注册失败 | 红字提示 |
| `token.expiring` / `token.refreshed` | 会话将过期 / 已刷新 | 写日志 |
| `agent.statusChanged` | 坐席状态变化 | 更新坐席标签 |
| `call.created` | 发起或收到一路通话 | 刷新当前通话 |
| `call.incoming` | 来电 | 弹来电浮层 |
| `call.stateChanged` | 通话状态变化 | 刷新状态标签、写 SIP 日志 |
| `call.activeChanged` | 当前通话切换 | 刷新当前通话 |
| `call.ended` / `call.failed` | 通话结束 / 失败 | 收起浮层、提示错误 |
| `error` | 其他 SDK 错误 | 红字提示 |

三个状态标签的文案与配色在 `src/lib/logs.ts` 里集中定义（沿用参考页的 class 词汇）：

| 维度 | SDK 取值 → 文案 |
|---|---|
| 坐席 | `available`→在线、`busy`→忙碌、`break`→休息、`offline`→离线 |
| 通话 | `dialing`→呼出中、`ringing`→振铃中、`connecting`→接通中、`active`→通话中、`held`→保持中、`ended`→已结束、`failed`→失败 |
| SIP | `registered`→已注册、`connecting`→连接中、`connected`→已连接、`reconnecting`→重连中、`failed`→注册失败、`offline`→未注册 |

## 7. 会话从哪来

SDK 需要的「会话」= 坐席账号 + SIP 密码 + 软电话 WSS 地址 + ICE/并发等策略。按网关能力有两种取法，
**由构建变量决定，页面里不切换**（`src/lib/session.ts` 的 `isLegacyPlatform()`）：

| 形态 | 什么时候用 | 切法 |
|---|---|---|
| 旧平台（**默认**） | 网关只有 `token/fs` + `seat/account/get` | 不用配，默认就是它 |
| 新平台 | 网关部署了 `/webphone/v1/*` | 构建时 `VITE_LEGACY_PLATFORM=0` |

### 7.1 默认：旧平台（会话由服务端拼好）

```
页面 ──POST /get-session──▶ 你们的服务端
                                   │ 1) {API主机}/openapi/v1/token/fs        拿 fs token
                                   │ 2) {API主机}/openapi/token/v1/seat/account/get
                                   │    请求头 Authorization: <fs token>     拿坐席账号
                                   │ 3) AES-128-CBC/Pkcs7 解出 SIP 密码
                                   │ 4) 拼 WSS 地址（带 ?token=）
                                   ▼
页面 ◀── 一份完整的 WebPhoneSession ──┘ ──▶ 交给 SDK（sessionProvider）发 REGISTER
```

放在服务端做的原因：**AES 密钥不下发浏览器，也不依赖网关的跨域配置**。示例实现见
`server/get-session.js`，接口契约：

| 项 | 值 |
|---|---|
| 方法/路径 | `POST /get-session`（同源；地址可用 `VITE_SESSION_API` 改） |
| 请求体 | `{ extension, host?, appKey?, appSecret?, sipWs?, registerExpires? }` |
| 成功响应 | SDK 的 `WebPhoneSession` JSON，关键字段见下表 |
| 失败 | 非 200，或 body 里带 `message` —— 页面会显示在红字行 |

`WebPhoneSession` 里 SDK 会读的字段：

| 字段 | 用途 |
|---|---|
| `sip.uri` / `sip.registrar` | REGISTER 的账号与 registrar |
| `sip.registerTicket` | SIP 密码（旧平台就是解出来的那个） |
| `sip.registerExpires` | REGISTER 有效期（秒），没给或非正数按 300 |
| `transport.wssUrl` | 软电话地址；`?token=` 原样保留，只剥离 `ticket` 参数 |
| `transport.ticket` | 走 `xcall-ticket.<ticket>` 子协议；为空则只声明 `sip` |
| `iceServers` | ICE 配置（旧平台给 `stun:turnIp:turnPort`，缺端口时用 3478） |
| `capabilities` | `outbound / inbound / mute / dtmf / hold / blind_transfer` |
| `expiresAt` | 会话过期时间（秒）；SDK 会据此提前刷新 |

### 7.2 可选：新平台（SDK 自己换会话）

```
页面 ──POST /get-token──▶ 你们的服务端 ──X-Ca 签名──▶ {API主机}/openapi/v1/webphone/tokens
                                                              │
页面 ◀── { accessToken, expiresAt } ─────────────────────────┘
   │
   └─ 交给 SDK（tokenProvider）──▶ SDK 自己请求 /webphone/v1/sessions 拿会话并发 REGISTER
```

页面对服务端的要求（`src/lib/session.ts` 的 `createTokenProvider`）：

| 项 | 值 |
|---|---|
| 方法/路径 | `POST /get-token`（同源；地址可用 `VITE_TOKEN_API` 改） |
| 请求体 | `{ platform: "web", extension }`，本地代理模式还会带 `host / appKey / appSecret / sipWs / registerExpires` |
| 成功响应 | `{ accessToken: string, expiresAt?: number(秒), extension?: string }` |
| 失败 | 非 200，或 body 里带 `message` |

**分机号建议由服务端登录态决定**，不要采信浏览器传上来的值；`extension` 字段可以留空不处理。

### 7.3 相关配置项

| 变量 | 作用 |
|---|---|
| `VITE_API_HOST` | 构建时注入默认「API 主机」（不注入就留空，用户在设置里填） |
| `VITE_LEGACY_PLATFORM=0` | 切到新平台形态（默认 1，即旧平台） |
| `VITE_SESSION_API` / `VITE_AGENT_STATUS_API` / `VITE_TOKEN_API` | 覆盖取会话 / 坐席状态 / 取 Token 的地址 |
| `VITE_WEBPHONE_API_BASE` | 让新平台的 `/webphone/v1/*` 直连别处（跳过同源代理） |
| `CC_WEBPHONE_TOKEN_PATH` | 新平台 Token 路径，默认 `/openapi/v1/webphone/tokens` |
| `CC_FS_TOKEN_PATH` | 旧平台 fs token 路径，默认 `/openapi/v1/token/fs` |
| `CC_SEAT_ACCOUNT_PATH` | 旧平台坐席账号路径，默认 `/openapi/token/v1/seat/account/get` |
| `CC_SEAT_STATUS_PATH` | 旧平台坐席状态路径，默认 `/openapi/token/v1/seats/set-status` |
| `CC_SIP_WS_PATH` | 旧平台软电话路径，默认 `/api/fs/sip-ws` |

## 8. 部署

`npm run build` 产出纯静态 `dist/`，但同源请求需要反代到后端：

| 路径 | 转发到 | 什么时候用 |
|---|---|---|
| `/get-token` | 你们的签发服务（本地开发时是 `node server/token-server.js`） | 新平台形态 |
| `/get-session` | 你们的会话服务 | 默认（旧平台） |
| `/set-agent-status` | 同上（坐席状态：空闲 / 置忙 / 休息 / 退签） | 默认（旧平台） |
| `/webphone/v1/*` | 平台的 WebPhone API | 新平台形态 |

nginx 片段（按需保留）：

```nginx
location /get-token   { proxy_pass http://127.0.0.1:3000; }
location /get-session { proxy_pass http://127.0.0.1:3000; }
location /set-agent-status { proxy_pass http://127.0.0.1:3000; }
location /webphone/   { proxy_pass https://你们的接口网关; proxy_set_header Host $host; }
```

本地开发由 `.env` 里的 `WEBPHONE_PROXY_TARGET` 配（`npm run dev` 会读）。没有反代时，
签入会卡在「获取 Token 失败」或「获取坐席账号失败」。

## 9. 日志与排障

面板分两个页签：

- **日志**：流程类信息 —— 签入、取 Token、坐席账号、连接状态、通话状态（来源 `app / token / seat / status / call / ccbar`）。
- **SIP**：SIP 原文（`REGISTER` / `INVITE` 与响应）以及 SDK 的 `call.*` 事件明细（来源 `sip / jssip / call`）。

每行格式 `HH:MM:SS.mmm [来源] 内容`，颜色按级别：绿=成功、黄=提醒、红=错误。
`token=` 与 `"password"` 会自动打码，API KEY / SECRET 不写日志。

**SIP 原文是固定开启的**：SDK 没有公开读 SIP 报文的接口，示例通过打开 JsSIP 的 debug 命名空间
（`localStorage.debug = 'JsSIP:*'`）拿到原文，再拦截 console 写进面板。注意两点：它属于 SDK 未公开的
调试能力；JsSIP 在首次签入时才加载，所以必须在签入前打开（页面在 `onMounted` 里做）。

常见现象与排查方向：

| 现象 | 排查方向 |
|---|---|
| 点签入没反应 / 红字「请填写 API 主机」 | 设置里 API 主机要带 `http(s)://` |
| 「Token 接口返回了非 JSON 响应（HTTP 404）」 | 打到文档站了，或者当前是新平台形态（`VITE_LEGACY_PLATFORM=0`）而网关没有 `/openapi/v1/webphone/tokens` —— 去掉该变量即回到默认的旧平台形态 |
| 「获取坐席账号失败」 | `/get-session` 没反代到后端；或网关没有 `seat/account/get`（用 `CC_SEAT_ACCOUNT_PATH` 改路径） |
| 点「置忙 / 休息 / 空闲」报 `Data not found` | 平台按**坐席账号**查坐席：确认传的 `extension` 是 `seat/account/get` 返回的 `username`（可能带企业前缀） |
| 点「置忙 / 休息」报接口不存在 | `/set-agent-status` 没反代；或网关没有 `seats/set-status`（用 `CC_SEAT_STATUS_PATH` 改路径） |
| 一直是「连接中」 | WSS 地址、证书、端口、路径；自签名证书先在浏览器里信任一次 |
| 打不通 / 提示 SIP 未连接 | 等 SIP 标签变「已注册」再呼叫 |
| 刚签入第一通必失败、第二通正常 | 平台行为（首个外呼回 480）；页面按 1.5s / 3s / 6s 自动重拨兜底，每次签入最多 3 次，接通过 / 退签 / 额度用完就停 |
| 分机显示带前缀 | 旧平台账号形如 `p8001`，页面会用 `customerPrefix` 去掉前缀后显示 |
| 页面离开后还有声音 | 组件销毁要 `dispose()`；本示例在 `onBeforeUnmount` 里做 |

## 10. 常见问题与安全建议

**API KEY、API SECRET、Token、SIP 密码不得出现在前端源码、日志、URL 或代码仓库里。**
本示例里它们只存在两处：设置弹窗（存 localStorage）与发给本地代理的请求体；换成你们自己的
后端后，这些字段可以完全不发给浏览器，由服务端按登录态决定分机。

上线前建议逐项验证：签入 → 注册 → 来电弹屏 → 接听 → 外呼 → 保持/恢复 → 转接 → 挂断 → 退签 →
刷新页面重签；并检查代理接口的访问权限、来源限制与频率限制。

另外两点：

- **一个页面只留一个客户端实例**：重复创建会出现两个 REGISTER 抢同一个坐席。
- **别把 SDK 的调试能力当稳定接口**：SIP 原文依赖 JsSIP 的 debug 命名空间，升级 SDK 时要复查。

## 11. 附录：与旧版脚本 SDK 的对照

| 旧版（`window.CCBarSDK`） | 现在（`CCBarClient`） |
|---|---|
| `<script src="ccbar.js">` 等四个文件 | `npm i @16x/webphone-sdk`，`import { CCBarClient }` |
| `new CCBarSDK({ eventHandle })` | `new CCBarClient({ tokenProvider \| sessionProvider })` |
| `ccbar.login(config)` | `await client.connect({ extension })` |
| `ccbar.signOut()` | `await client.disconnect()` / `dispose()` |
| `ccbar.call(number)` | `await client.dial({ destination })` |
| `ccbar.insideCall(number)` | `await client.dial({ destination: prefixExtension(number, 企业前缀) })` |
| `ccbar.answer(sessionId?)` | `await client.answer(callId)` |
| `ccbar.hangup()` | `await call.hangup()` |
| `ccbar.holdCall()` / `unholdCall()` | `await call.hold()` / `call.resume()` |
| `ccbar.transSo(isIn)` | `await call.transfer({ type: 'blind', target })` |
| `ccbar.setId()` / `setRe()` | `client.setAgentStatus('available' \| 'break')` |
| `ccbar.setBu()` | 已废弃（新 SDK 无 busy） |

| `onRecviceCall(number, data)` | `client.on('call.incoming', …)` |
| `onError` / `onRequestError` | `client.on('error', …)` / `call.failed` / `connection.failed` |
| 密码来自 `/seat/account/get` + 前端 AES 解密 | 同样的流程，但放在服务端（`server/get-session.js`） |
