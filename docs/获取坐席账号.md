## 获取坐席账号（SIP 注册账号信息）

### 1. 描述
获取坐席账号
获取当前 token 所绑定坐席的 SIP 注册账号信息（SIP 用户名/密码、WS/WSS 端口、域名、TURN/ICE 配置等），
用于网页软电话(Webrtc)注册与外呼。**该接口无分页、无请求参数，返回单个账号对象** —— token 由
「获取token」接口按分机签发，绑定哪条分机即返回哪条的账号。

### 2. url
```
POST http://ip:port/openapi/token/v1/seat/account/get
```

### 3. 请求格式
```
POST /openapi/token/v1/seat/account/get HTTP/1.1
Host: ip:port
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.xxxxx.yyyyy
Accept: */*
Connection: keep-alive
Content-Length: 0
```
（无请求体）

### 3.1 授权认证例子
本接口使用 Bearer Token 鉴权，token 由「获取token」接口换取：

**第一步：用签名头调用获取token，换取 token**
```
POST /openapi/v1/token/fs HTTP/1.1
Host: ip:port
X-Ca-Key: 8S8n5jxbf5WLL7g3
X-Ca-Timestamp: 1753428668463
X-Ca-Signature: dd5e932872eb745d2380bd476a5e111...
X-Ca-Signature-Method: HMAC-SHA256
X-Ca-Nonce: u4cv7mv9hyixrg1n
Content-Type: application/json

{
    "extension": "8001"
}
```
响应：
```
{
    "code": 0,
    "message": "Success",
    "data": {
        "token": "eyJhbGciOiJIUzI1NiIs...",
        "expires": 1753432268,
        "extension": "8001",
        "seatNum": "05106807262"
    }
}
```

**第二步：携带 token 调用本接口**（见第 3 节）

签名算法（第一步用）：
- `content = MD5(请求体原文)`
- 将 appKey、content、nonce、timestamp 四个值按 key 升序排列后**仅拼接值**：
  `canonical = appKey + content + nonce + timestamp`
- `X-Ca-Signature = HMAC-SHA256(canonical, appSecret)` 的十六进制小写
- 时间戳与服务器时差不得超过 ±5 分钟；nonce 5 分钟内不得重复

### 4. 参数说明

**(1) authentication 域说明**

| 字段名 | 类型 | 是否必填 | 字段说明 | 备注说明 |
|---|---|---|---|---|
| Authorization | string | Y | 登录令牌 | 格式 `Bearer <token>`；token 来自 `/openapi/v1/token/fs`，与分机绑定，过期后需重新换取 |

**(2) request 域说明**

无请求参数（无 body、无 query）。

### 6. 响应说明

**(1) result 域说明**

| 字段名 | 类型 | 字段说明 |
|---|---|---|
| code | int | 业务状态码，0 表示成功 |
| message | string | 状态描述 |
| data | object | 账号数据，失败时为 null |
| timestamp | int | 服务器时间戳（秒） |
| traceID | string | 链路追踪 ID，排查问题时提供此值 |

**(2) data 域说明**

| 字段名 | 类型 | 字段说明 | 备注说明 |
|---|---|---|---|
| apiKey | string | 调用方 API Key | 与换取 token 的 X-Ca-Key 一致 |
| customerPrefix | string | 企业前缀 | SIP 用户名的前缀部分 |
| extension | string | 内部分机号 | 不含企业前缀 |
| username | string | SIP 注册用户名 | 企业前缀 + 内部分机，网页软电话注册用 |
| password | string | SIP 注册密码 | |
| registerPassword | string | 短时注册凭据 | 可能有值也可能缺省；临时注册票，过期自动失效 |
| expiresIn | int | 短时注册凭据有效秒数 | 与 registerPassword 配套，缺省表示未启用 |
| wsPort | int | SIP WebSocket 端口 | ws 明文 |
| wssPort | int | SIP WebSocket 端口 | wss 加密，浏览器用这个 |
| domain | string | SIP 域名 | 注册域 |
| turnIp | string | TURN 服务器地址 | WebRTC 中继 |
| turnPort | int | TURN 服务器端口 | |
| turnUserPassword | array | TURN 账号密码组 | [用户名, 密码] |
| iceServers | array | WebRTC ICE 配置 | STUN/TURN 列表，直接喂给 RTCPeerConnection |
| agentTerminal | string | 坐席终端类型 | web/ccbar/APP-Android/PC-* 等 |
| desktopOnline | bool | 该分机是否被桌面端占用 | true 时浏览器端需注意抢占 |

**(3) iceServers 域说明**

| 字段名 | 类型 | 字段说明 |
|---|---|---|
| urls | array | ICE 服务器地址列表（stun:/turn:） |
| username | string | TURN 用户名（可能缺省） |
| credential | string | TURN 密码（可能缺省） |

**(4) 错误码说明**

| code | 说明 | 处理建议 |
|---|---|---|
| 0 | 成功 | — |
| 61 | 未授权：token 缺失/无效/过期，或调用方 IP 不在白名单 | 重新走「获取token」换取 token；确认白名单已加调用方出口 IP |
| 65 | 资源不存在（如分机未分配坐席 Seat not assigned yet） | 确认 extension 正确且已绑定坐席 |
| 55 | 操作不允许 | 联系平台方核查账号归属 |
| 50 | 内部错误 | 携带 traceID 联系平台方排查 |

## 每个值是谁给的

| 会话字段 | 来源 |
|---|---|
| `sessionId` | 服务端自己生成（示例：`legacy-` + 时间戳 base36） |
| `expiresAt` | `now + min(fs token 的 expires, 坐席账号的 expiresIn) - 180`，且不小于 60 |
| `agent.*` | 坐席账号接口的 `username`（四个字段都填它；`status` 固定 `Available` 起步，由 SDK 事件驱动更新） |
| `sip.uri` / `sip.registrar` | `sip:{username}@{domain}`、`{domain}` —— `domain` 取自坐席账号接口 |
| `sip.registerTicket` | 坐席账号接口的 `password`（AES-128-CBC/Pkcs7 解出来的**明文**） |
| `sip.registerExpires` | 服务端决定（示例 600）；SDK 拿不到有效值时才回退 300 |
| `sip.ticketExpiresIn` / `transport.ticketExpiresIn` | 与上面 `expiresAt` 的 TTL 同值，仅作展示 |
| `transport.wssUrl` | `wss://{domain}/api/fs/sip-ws?token={fs token}`（端口 443 时不带端口） |
| `transport.ticket` | 旧平台没有 ticket 子协议 → **空串**（SDK 只声明 `sip`） |
| `iceServers` | 坐席账号接口的 `turnIp`/`turnPort`（缺省 3478），拼成 `stun:` 地址 |
| `policy` | 服务端策略，四个开关 —— 见下面「两个策略字段怎么填」 |
| `capabilities` | 能力白名单 —— 老平台六项原样给出，见下面「两个策略字段怎么填」 |
| `customerPrefix` / `username` | SDK **不读**，只是给页面显示分机（标题栏显示 `200002 · 10006`）时去掉前缀用 |


### `capabilities`：能力白名单（列了才放行）

SDK 拿它当开关用，**没有列出的能力，对应操作会直接抛 `CAPABILITY_NOT_SUPPORTED`**：

| 值 | 管什么 | 缺了会怎样 |
|---|---|---|
| `outbound` | 外呼 `dial()` | 外呼抛错 |
| `inbound` | 接来电 `answer()` | 抛错；而且 `policy.incomingEnabled=false` 时本来也不会接来电 |
| `mute` | `call.mute()` / `call.unmute()` | 抛错 |
| `dtmf` | 通话中按键 `call.sendDtmf()` | 抛错 |
| `hold` | `call.hold()` / `call.resume()` | 抛错（移动端形态本来不支持，SDK 会自行删掉） |
| `blind_transfer` | 盲转 `call.transfer()` | 抛错（同上） |

老平台这六项都支持，**原样返回即可**，不用刻意少填 —— 少填只是让页面上的按钮点了报错，不增加安全性。

### `policy`：通话策略（四个开关）

| 字段 | 作用 | 桌面 | 移动 H5 |
|---|---|---|---|
| `maxConcurrentCalls` | 同时最多几路通话 | `2` | `1`（移动端 SDK 也会压到 1 路） |
| `incomingEnabled` | 是否接来电（总闸） | `true` | `true` |
| `mobileIncomingEnabled` | 移动端形态下是否接来电（SDK 3.1.4+） | 随意 | **必须 `true`** |
| `backgroundCallingSupported` | 页面切后台后是否还能通话 | `false` | `false`（iOS / Android 都不保证，别写 `true`） |

> **来电能被接起，要三件事同时成立**：`policy.incomingEnabled = true` + `capabilities` 里有 `inbound` +
> 移动端还要 `policy.mobileIncomingEnabled = true`。
> 少任何一个的表现都是「自己能打出去、别人打不进来」，主叫侧看到平台转出来的
> `480 Temporarily Unavailable`（`Q.850;cause=16`），页面上连来电浮层都不弹。
